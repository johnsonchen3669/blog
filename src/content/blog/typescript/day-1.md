JavaScript 給了我們很高的開發自由，但當專案變大、團隊擴張，或開始與 AI 一起寫程式時，「這段程式碼到底假設了什麼？」就會變成一個很重要的問題。

TypeScript 不只是幫 JavaScript 加上型別標記。它更像是一種思考工具：幫我們把資料的形狀、程式的狀態與不能發生的情況說清楚。

這個 30 天系列會從 JavaScript 開發者熟悉的概念出發，逐步建立 TypeScript 的型別思維，並把它放進 AI 協作的實際情境中。

## 這 30 天會學到什麼

- 從 JavaScript 的動態資料理解靜態型別
- 為函式、物件與資料流程建立清楚的型別
- 使用 union、generic 與 narrowing 表達真實的商業邏輯
- 讀懂型別錯誤，判斷該修正程式還是型別
- 用 TypeScript 檢驗 AI 產生的程式碼與隱藏假設

## 系列文章適合誰

這個系列適合已經會寫 JavaScript，但對 TypeScript 還不熟悉，或是曾經使用過 TypeScript，卻總覺得自己只是在「補型別」的開發者。

你不需要先背完所有語法。接下來的每一天，我們會從一個具體問題開始，學會如何讓型別成為設計與溝通的一部分。
